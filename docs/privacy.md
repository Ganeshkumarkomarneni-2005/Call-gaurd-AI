# CallGuard AI — Privacy Policy

**Document ID:** PRIV-001  
**Version:** 1.0  
**Date:** 2026-09-17  
**Status:** Draft  

> **Legal Disclaimer:** This document describes the technical privacy architecture of the CallGuard AI system. It is NOT a legal document and does NOT constitute legal advice. Operators deploying this system must consult qualified legal counsel to ensure compliance with applicable laws including the Indian IT Act, TRAI regulations, DPDP Act 2023, and GDPR where applicable.

---

## 1. Call Recording Policy

### 1.1 What CallGuard AI Does NOT Store

**Audio is NEVER persisted.**

CallGuard AI processes incoming audio in-memory via the STT (Speech-to-Text) pipeline and immediately discards the audio data. No audio files are written to disk, database, or any storage system.

### 1.2 What CallGuard AI DOES Store

CallGuard AI stores the **text transcript** of the caller-side conversation only:
- The caller's spoken words (converted to text via STT)
- The system's responses (text generated by the Conversation Agent)
- Classification metadata (intent, risk score, action taken)

**The recipient's voice is never recorded.** Transcription only applies to the intercepted caller-side conversation before the call is connected to the recipient.

### 1.3 Recording Justification

The transcript is stored for:
1. **Safety:** Enabling review of blocked calls to detect false positives
2. **Audit:** Providing recipients with an explanation of why a call was blocked
3. **Model improvement:** (Only with explicit opt-in) Improving ML classification accuracy
4. **Legal compliance:** Maintaining records in case of fraud investigation referrals

## 2. Transcript Retention

| Data | Default Retention | Configurable |
|------|------------------|-------------|
| Call transcripts | 90 days | Yes (30–365 days) |
| Risk scores and metadata | Indefinite (until user deletion) | No |
| Authentication logs | 30 days | No |
| Audit logs | 1 year | No |

Transcripts older than the retention period are automatically deleted via a scheduled background job. Deletion is permanent (hard delete from database, not soft delete).

## 3. PII Handling

### 3.1 What PII May Be Present

Caller transcripts may contain the following PII provided voluntarily by the caller:
- Caller's name
- Organization name
- Phone number (stored as system metadata from telephony provider)
- Salary/financial information (in recruitment calls)
- Any other information the caller volunteers

### 3.2 PII Minimization Principles

- CallGuard AI does NOT prompt callers for PII beyond what is needed for classification ("Please state your name, organization, and purpose")
- PII in transcripts is stored only as part of the raw transcript text — it is NOT extracted into separate searchable fields (exception: recruitment info extraction for legitimate recruiter calls, where structured data helps the recipient evaluate the call)
- Phone numbers are stored as-is from the telephony provider — they are NOT enriched with external data

### 3.3 PII in Logs

**STRICT POLICY: No PII is ever written to application logs.**

```
✅ PERMITTED in logs: call_id, risk_level, action, timestamp, duration_seconds
❌ PROHIBITED in logs: phone numbers, names, transcript text, email addresses
```

This is enforced by code policy and reviewed in all PRs.

## 4. Data Deletion

### 4.1 User-Initiated Deletion

Recipients may request deletion of their call history at any time via:
- Dashboard: Settings → Privacy → Delete Call History
- API: `DELETE /api/v1/calls` (authenticated)

Deletion cascades to:
- All `call_transcripts` records
- All `call_classifications` records
- All `recruitment_info` records

What is NOT deleted:
- Aggregate statistics (non-PII summary data used for system performance monitoring)
- Audit log entries (retained for legal compliance per retention schedule)

### 4.2 Account Deletion

Upon account deletion:
1. All call records and transcripts are immediately deleted
2. User record is anonymized (email replaced with hash, name removed)
3. Anonymized record retained for audit log integrity for 1 year, then fully deleted

### 4.3 Automated Retention Enforcement

A background job runs daily to delete expired transcripts. This job:
- Identifies call records older than the configured retention period
- Hard deletes transcript text (replaces with NULL or deletes rows)
- Logs deletion count (without any PII) to the audit log

## 5. Data Access Controls

### 5.1 Who Can Access Data

| Role | Access |
|------|--------|
| **Recipient (account owner)** | Their own call history, transcripts, risk scores |
| **Admin** | All call records in the deployment (with audit logging) |
| **System (AI pipeline)** | Read/write during active call processing only |
| **Third parties** | None — no third-party data sharing without explicit consent |

### 5.2 Technical Access Controls

- All API endpoints require JWT authentication
- Call records are scoped by user — users can only access their own data via API
- Admin access requires a separate admin role claim in JWT
- Database access is restricted to the backend application service (no direct external access)
- Database credentials are in environment variables, not in source code

## 6. Consent Requirements

### 6.1 Caller Consent

CallGuard AI intercepts and transcribes the caller's speech. Depending on the jurisdiction, this may require:
- **Announcement:** The system plays a greeting that informs the caller they are interacting with an automated screening system
- **Default greeting includes:** "This call is being screened by an automated system to protect the recipient from unwanted calls."

Operators are responsible for ensuring their greeting script meets local legal requirements for call interception notification.

### 6.2 Recipient Consent

Recipients who use CallGuard AI consent to:
- Inbound call screening before their phone rings
- Storage of call transcripts for the configured retention period
- Receipt of push notifications about call status

### 6.3 No Consent Required For

- Blocking a call that is classified as fraudulent — this is a protective action that does not require the fraudulent caller's consent

## 7. Indian Telecom Privacy Context

> Reference only — consult legal counsel for compliance requirements.

**Relevant Indian regulations:**
- **TRAI Do Not Disturb (DND) Regulations:** CallGuard AI is a recipient-side screening tool, not a telemarketer. These regulations apply to the callers, not to CallGuard.
- **Digital Personal Data Protection (DPDP) Act, 2023:** Operators must ensure compliance regarding collection, processing, and storage of personal data of callers and recipients.
- **Information Technology Act, 2000 (Section 43A):** Requires reasonable security practices for sensitive personal data.
- **TRAI Customer Preference Registration (TCPR):** CallGuard AI operates independently of TCPR — it screens calls that have already passed through carrier-level filters.

**Key obligations under DPDP Act (reference):**
1. Data Principal rights: Callers and recipients have rights to access and deletion of their data
2. Data Fiduciary duties: The operator must have a lawful basis for processing
3. Data localization: At time of writing, no mandatory localization for non-sensitive data
4. Cross-border transfer: Restrictions apply if data is stored outside India

## 9. User Controls

Recipients have the following self-service privacy controls:

| Control | Location | Effect |
|---------|---------|--------|
| Delete individual call record | Dashboard → Call history → Delete | Removes transcript + classifications |
| Delete all call history | Settings → Privacy → Delete all | Removes all call records |
| Delete account | Settings → Account → Delete account | Full data deletion + anonymization |
| Configure retention period | Settings → Privacy → Retention | Sets transcript retention (30–365 days) |
| Export call history | Settings → Privacy → Export | Downloads JSON of all call records |
| Opt out of model improvement | Settings → Privacy → Data use | Prevents transcript use for ML training |

---

## 10. Security Measures for Privacy

- All data in transit encrypted via HTTPS/TLS
- Database encryption at rest (managed PostgreSQL providers) or configurable
- Database backups encrypted
- No transcript data sent to third-party analytics services
- ML model training on user data requires explicit opt-in (default: off)
- Penetration testing recommended before production deployment
